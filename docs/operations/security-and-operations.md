# TickWitness 安全、发布与长期运维

更新：2026-11-19，Asia/Singapore。当前支持的信任边界按 S13-01 冻结的 [Execution trust v1](../contracts/execution-trust-v1.md) 与 [ADR0044](../adr/0044-explicit-execution-trust-boundaries.md) 说明；已接受的 CLI、SDK、Job 与资源能力见[分版本支持](../support.md)和[Sprint12状态](../planning/sprint-12-status.md)。下文的产品级隔离、服务 SLO、发行与通用恢复流程仍是目标要求，不因已有部分组件而成为已实现或已验收保证。

## 信任边界与威胁模型

行情文件、证据包、登记的策略源码与 Agent 输出需要按其入口合同验证，内容通过解析或哈希检查不等于来源可信。当前 `.py` 源码冻结只读取有界字节、检查语法并绑定哈希，不执行该源码；native 路径只运行已资格的内置策略。owner、输入/存储根及祖先、解释器、依赖和 coordinator 属于当前信任基础。若运行恶意代码或受损依赖，它可能读取 secrets、联网、fork、耗尽资源或伪造输出；现有输入校验和子进程不能提供这种代码的安全隔离。

| 运行模式 | 当前状态与范围 | 限制及后续门槛 |
| --- | --- | --- |
| M0 可信本地 | 当前支持的信任边界，仅限现有已资格内置 profile；单 owner 远端机器也可采用此模型 | 同 UID 的宿主文件权限和继承环境仍可信；没有默认拒绝网络、独立身份或 mount/chroot 边界。未提供 HTTP/MCP listener，不支持任意 Python 策略 |
| M1 受限单机隔离 | 仅要求集合；未实现、未资格、关闭，没有可启用的 mode 参数 | 先选择具体环境/机制/数字限额，再验证只读输入与 TCB、隔离身份/环境/FD、私有 scratch、OS 网络拒绝、整棵任务树及总存储限额、终止与回收。缺控制或证据就保持不可用 |
| M2 不支持托管 | 不支持不可信任务托管、需要独立用户身份/权限的协作服务及公共多租户 | 租户身份、归属、权限、秘密和资源隔离、服务安全与运维需另行验收；普通容器、自托管或单项 M1 成功不会自动开放此模式 |

这些是文档标签，不是已有 CLI/SDK 选项。Python 子进程、`-I`、提示词、测试 monkeypatch 或文件哈希都不是恶意代码沙箱。安全文件入口的 dirfd/no-follow、常规文件与字节/变化检查只作用于可信根下的入口，不提供硬链接、恶意祖先、同 UID 进程或 host owner 的秘密隔离。哈希闭包可以检查相对已提供锚点的一致性，不能认证作者、真实行情来源或防止 owner 同时替换全部锚点；外部签名/信任锚也需要另立合同与验收，当前没有该保证。

当前窄 IPC 不传递 native worker 的 Catalog/ledger 路径，coordinator 保留逻辑上的校验与最终发布权；路径未传递不等于 same-UID worker 无法接触宿主文件。配置了 Job controls 的任务有其冻结 CPU、单文件、FD、deadline 和 owned scratch 回收控制；并非所有历史命令均有这些默认值，也没有整树 RAM/PID/CPU、总磁盘/inode、环境清洗、网络拒绝或恶意逃逸进程的保障。资源观测不是限额；停止不确定、仍有 lifetime 或 scratch 已替换时保留诊断，不制造安全停止或物理回收成功。

只读输入/TCB、仅私有受配额 scratch 可写及执行侧不得修改判定/最终索引，是 M1 尚未实现的要求。现有离线 verifier、封闭格式、禁止可执行反序列化及各类包的大小/数量/路径检查按各自合同成立，不把未来通用上传/解压安全要求当作已提供接口。机密数据的公开许可、日志脱敏和无默认内容上传同样需遵守；不能用本地证据完整性替代宿主保密。

后续 M1 攻击验收和独立安全复核必须记录真实环境、控制、输入/输出与未满足项，不能从文档或旧 CI 推断通过；原协议预算、已提交结果和未知 reservation 的语义不因模式改变而重置。外部真人复验仍为 0/0/PENDING，独立安全复核尚未进行，两者分开记录。

## MCP 与 HTTP

当前只有已限定的 CLI 与 SDK 入口，SDK v1 不开放执行、Job 或维护方法。HTTP/MCP 尚未实现、没有 listener，需求决定为条件性 DEFER，见[需求与当前决定](../support.md#httpmcp-入口需求与当前决定)。未来入口必须复用应用服务和既有权限/协议校验，采用严格 schema；Agent 输出是提案，不能自行增权、伪造 available-at、修改判定或绕过原预算。窄 API 本身不代替 M1/M2 的宿主/服务权限边界。

本地 stdio MCP 与 loopback HTTP 是未来 transport 设想，不是本轮交付或已测安全 profile。是否暴露 listener 需另外授权与验收；远程服务开启前必须实现身份/资源归属、最小权限 scopes、速率及预算限制、审计、令牌撤销与 TLS 部署说明。禁止 token passthrough、用户可控任意 URL 抓取和从工具返回内容执行指令。安全规范版本随实现固定，不跟随 `latest` 静默改变。参考 [MCP security best practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)。

## 数据与权限

每个数据源记录来源、获取方式、许可/条款链接、允许用途、是否可再分发、归属、删除/到期规则及检查日期。免费接口不自动意味着可公开再分发。公共测试集优先使用自生成语料或明确授权的切片，示例数据不得混入个人成交与 API keys。

catalog 只保存元数据与 artifact 引用，敏感原始数据不入 Git。运行制品按输入许可和用户保留策略回收；删除前保留可解释的 tombstone，不能悄悄让旧报告仍显示可验证。备份、日志与 error traces 同样适用脱敏和数据访问控制。

## 发布与依赖

Python 核心与 CLI 拟采用单一版本；可选引擎、MCP 与 UI 通过兼容矩阵发布，避免相互独立但无法组合的十几个包。默认发行目标先为 Linux x86_64、macOS arm64，具体 Python 版本在 Sprint 1 按引擎 wheel 支持确认；Windows 先通过 WSL2 路径，不在未测时宣称原生支持。

依赖采用 lockfile，官方 Action pin 完整提交 SHA；PR 工作流只读权限且无发布凭据，不使用 `pull_request_target` 执行 PR 代码。依赖升级由计划化 PR 加契约回归处理。许可证清单覆盖直接/传递依赖、引擎与示例数据，选择默认引擎前检查分发方式和许可兼容性。

发行流程：变更记录 → 版本/契约审查 → 固定矩阵 CI → 安全与许可扫描 → 生成 SBOM → 构建 wheel/镜像和证据语义清单 → RC 安装/迁移/回滚演练 → owner 发布 → smoke check。PyPI Trusted Publishing/OIDC、镜像签名和制品 attestations 是计划要求，实现后才能称已保障；不把长期 token 写入仓库。

采用 SemVer 描述公开 API 兼容性，数据/证据 schema 独立版本。v1 稳定接口的破坏性变化需 major version；普通弃用至少保留两次 minor release 且不少于90天。依赖紧急安全例外需公告。历史 verifier 保留可安装版本或受限兼容执行路径，旧格式 unsupported 要有明确理由与升级办法。

## 可观察性与初始 SLO

所有服务日志包含 run/job/claim/scenario/trace ID、状态转换及结构化错误码；禁止默认记录完整策略与原始消息。指标包括 ingest gap/latency、quarantine、job queue/leases/retry/cancel、CAS 校验失败、search budget、verifier mismatch、CPU/RAM/磁盘及输入许可到期。

| SLI | 初始目标 | 约束 |
| --- | --- | --- |
| 有效请求服务可用性 | 自托管 beta 试运行窗口内 ≥99.5%/30天 | 先收集基线；不是单人全天人工支持承诺 |
| 最终制品完整性 | 所有标记 complete 的制品通过 manifest 校验 | 一次静默损坏即阻止相关发布 |
| 重复任务副作用 | 相同幂等键不能产生冲突最终判定 | 允许至少一次执行，最终提交需去重 |
| job 可见性 | 状态查询 p95 <500ms，固定参考负载 | replay/search 完成时长另列 |
| 备份恢复 | beta 参考数据量 RPO≤24h、RTO≤4h | 需实际恢复演练；小型自托管目标 |

任务状态与完成制品分别提交：先写临时文件、校验内容、在同一文件系统原子发布，再以事务记录引用；对象存储使用不可变 key/显式 commit manifest。没有一致提交的制品不可标 complete。SQLite 使用受支持备份机制，不能随意复制打开的 DB 文件冒充可恢复备份。

## 必需 runbooks

| 场景 | 操作及验证 |
| --- | --- |
| 采集断连/序列缺口 | 标记缺口、冻结受影响区间的可信回放、重同步；不得制造丢失历史 |
| worker 崩溃/lease 过期 | 区分未提交与已提交制品，幂等重试并保留 attempt；无重复判定 |
| catalog 与 CAS 不一致 | 隔离损坏、校验可达引用、修复/重算；报告结果 invalidated |
| 磁盘满/预算耗尽 | 停止接收新任务，有界结束当前任务，保留恢复信息和停止原因 |
| verifier 不一致 | 隔离相关引擎/版本，保存输入，停止发布受影响判定，建立缺陷和影响范围 |
| 版本升级失败 | 迁移前备份，使用兼容版本/恢复快照；破坏性数据迁移不假设 down migration 永远可行 |
| 安全漏洞 | 暂停相关能力、撤销受影响凭据、私下协调修复，发布影响范围与修复版本 |

首次导入/核验外部文件前完成路径、symlink、大小配额与禁止可执行反序列化的负例；beta 前完成 worker失败、制品不一致、磁盘满和最小备份恢复演练。分版本迁移、全量runbooks及升级回退在S18/S19完成，v1前重跑关键恢复与支持范围内的恶意任务限制。演练记录需有输入规模、操作人、时间、结果和未满足项。

## 长期维护与生态

初始只支持当前 minor 和上一 minor 的关键修复；是否建立长期支持版本取决于维护者预算和真实用户需求。每月依赖与数据源检查，每季度恢复演练/接口兼容检查，每半年评估领域边界和支持矩阵。

adapter/第三方插件必须声明版本范围、数据权限、能力/未知项、资源与信任需求，并通过公开契约测试集。插件注册不等于安全审计背书。社区报告先脱敏，再由贡献者选择是否公开；禁止默认上传用户策略以换取支持。

v1 后托管服务、团队权限、账单和多租户隔离分别立项，必须有用户需求、单位经济测量和运维资源。按月记录支持、依赖升级与外部案例排错占总可用净工程容量的比例；连续两个月超过25%且挤占核心交付时冻结新集成、缩小支持矩阵。每Sprint15h质量预算还包含正常测试和评审，不能全部视为额外支持余量。
