# TickWitness 安全、发布与长期运维

状态：Proposed，2026-10-25。Sprint1基础已合并，S2数据证据分支已加入有界导入/inspection，实际验证见[开发入口](../development.md)与[S2状态](../planning/sprint-02-status.md)；下文产品级隔离、SLO、发行及恢复能力仍需逐步实现和演练。

## 信任边界与威胁模型

用户导入的策略代码、行情文件、证据包、引擎插件及 Agent 输出全部视为不可信输入。策略可能读本地 secrets、访问网络、fork bomb、耗尽磁盘、修改 test 数据或伪造输出。恶意证据包还可能利用路径穿越、符号链接、反序列化或解压炸弹。

| 运行模式 | 承诺范围 | 上线门槛 |
| --- | --- | --- |
| 本地可信代码 | 用户自己授权的策略与插件，进程隔离主要处理故障 | 明示可访问本机权限，默认不启动远程 listener |
| 单机不可信任务 | Linux 受限执行环境，策略与评价器分离 | 无网络/非root/只读输入/资源限制/无宿主socket与敏感挂载，实际逃逸与越权检查 |
| 自托管协作 | 身份、权限、配额、任务归属和管理员配置 | 安全边界、审计及恢复验收；只对声明的部署配置支持 |
| 公共托管多租户 | 独立租户边界及更强隔离 | v1 后单独 RFC、人员预算、威胁模型和外部安全复核；普通容器不能自动视为足够边界 |

Python 子进程、提示词或文件哈希都不是阻止恶意代码的安全沙箱。host owner 拥有全部文件时，不能宣称系统能对该 owner 隐藏测试集或防止其篡改全部证据；可提供可检测完整性及外部签名等更有限保证。

引擎执行策略不得拥有修改 frozen inputs、判定配置和最终证据索引的权限。verifier 在新环境重算，禁止 pickle 等可执行反序列化；导入包限制总大小、文件数量、压缩比、路径和 symlink。机密策略和行情默认保留本地，遥测默认关闭且不上传公式、订单或数据片段。

## MCP 与 HTTP

CLI、SDK、HTTP、MCP 调用同一应用服务和权限校验。工具参数采用严格 schema，用户不可绕过协议冻结直接调用原始数据库。Agent 不能选择自己的权限、伪造 available-at 或写判定；模型输出是提案，工具执行结果是记录。

初期 MCP 使用本地 stdio，HTTP 绑定 loopback。远程服务开启前必须实现身份/资源归属、最小权限 scopes、速率及预算限制、审计、令牌撤销与 TLS 部署说明。禁止 token passthrough、用户可控任意 URL 抓取和从工具返回内容执行指令。安全规范版本随实现固定，不跟随 `latest` 静默改变。参考 [MCP security best practices](https://modelcontextprotocol.io/docs/2026-07-28/tutorials/security/security_best_practices)。

## 数据与权限

每个数据源记录来源、获取方式、许可/条款链接、允许用途、是否可再分发、归属、删除/到期规则及检查日期。免费接口不自动意味着可公开再分发。公共测试集优先使用自生成语料或明确授权的切片，示例数据不得混入个人成交与 API keys。

catalog 只保存元数据与 artifact 引用，敏感原始数据不入 Git。运行制品按输入许可和用户保留策略回收；删除前保留可解释的 tombstone，不能悄悄让旧报告仍显示可验证。备份、日志与 error traces 同样适用脱敏和数据访问控制。

## 发布与依赖

Python 核心与 CLI 拟采用单一版本；可选引擎、MCP 与 UI 通过兼容矩阵发布，避免相互独立但无法组合的十几个包。默认发行目标先为 Linux x86_64、macOS arm64，具体 Python 版本在 Sprint 1 按引擎 wheel 支持确认；Windows 先通过 WSL2 路径，不在未测时宣称原生支持。

依赖采用 lockfile，官方 Action pin 完整提交 SHA；PR 工作流只读权限且无发布凭据，不使用 `pull_request_target` 执行 PR 代码。依赖升级由计划化 PR 加契约回归处理。许可证清单覆盖直接/传递依赖、引擎与示例数据，选择默认引擎前检查分发方式和许可兼容性。

发行流程：变更记录 → 版本/契约审查 → 固定矩阵 CI → 安全与许可扫描 → 生成 SBOM → 构建 wheel/镜像和证据语义清单 → RC 安装/迁移/回滚演练 → owner 发布 → smoke check。PyPI Trusted Publishing/OIDC、镜像签名和制品 attestations 是计划要求，实现后才能称已保障；不把长期 token 写入仓库。

采用 SemVer 描述公开 API 兼容性，数据/证据 schema 独立版本。v1 稳定接口的破坏性变化需 major version；普通弃用至少保留两次 minor release 且不少于90天。依赖紧急安全例外需公告。历史 verifier 保留可安装版本或受限兼容执行路径，旧格式 unsupported 要有明确理由与升级办法。

## 可观察性与初始 SLO

所有服务日志包含 run/job/claim/scenario/trace ID、状态转换及结构化错误码；禁止默认记录完整策略与原始消息。指标包括 ingest gap/latency、quarantine、job queue/leases/retry/cancel、CAS 校验失败、search budget、verifier mismatch、CPU/RAM/磁盘及输入许可到期。

| SLI | 初始目标 | 约束 |
| --- | --- | --- |
| 有效请求服务可用性 | 自托管 beta 试运行窗口内 ≥99.5%/30天 | 先收集基线；不是单人全天人工支持承诺 |
| 最终制品完整性 | 所有标记 complete 的制品通过 manifest 校验 | 一次静默损坏即阻止相关发布 |
| 重复任务副作用 | 相同幂等键不能产生冲突最终判定 | 允许至少一次执行，最终提交需去重 |
| job 可见性 | 状态查询 p95 <500ms，固定参考负载 | replay/search 完成时长另列 |
| 备份恢复 | beta 参考数据量 RPO≤24h、RTO≤4h | 需实际恢复演练；小型自托管目标 |

任务状态与完成制品分别提交：先写临时文件、校验内容、在同一文件系统原子发布，再以事务记录引用；对象存储使用不可变 key/显式 commit manifest。没有一致提交的制品不可标 complete。SQLite 使用受支持备份机制，不能随意复制打开的 DB 文件冒充可恢复备份。

## 必需 runbooks

| 场景 | 操作及验证 |
| --- | --- |
| 采集断连/序列缺口 | 标记缺口、冻结受影响区间的可信回放、重同步；不得制造丢失历史 |
| worker 崩溃/lease 过期 | 区分未提交与已提交制品，幂等重试并保留 attempt；无重复判定 |
| catalog 与 CAS 不一致 | 隔离损坏、校验可达引用、修复/重算；报告结果 invalidated |
| 磁盘满/预算耗尽 | 停止接收新任务，有界结束当前任务，保留恢复信息和停止原因 |
| verifier 不一致 | 隔离相关引擎/版本，保存输入，停止发布受影响判定，建立缺陷和影响范围 |
| 版本升级失败 | 迁移前备份，使用兼容版本/恢复快照；破坏性数据迁移不假设 down migration 永远可行 |
| 安全漏洞 | 暂停相关能力、撤销受影响凭据、私下协调修复，发布影响范围与修复版本 |

首次导入/核验外部文件前完成路径、symlink、大小配额与禁止可执行反序列化的负例；beta 前完成 worker失败、制品不一致、磁盘满和最小备份恢复演练。分版本迁移、全量runbooks及升级回退在S18/S19完成，v1前重跑关键恢复与支持范围内的恶意任务限制。演练记录需有输入规模、操作人、时间、结果和未满足项。

## 长期维护与生态

初始只支持当前 minor 和上一 minor 的关键修复；是否建立长期支持版本取决于维护者预算和真实用户需求。每月依赖与数据源检查，每季度恢复演练/接口兼容检查，每半年评估领域边界和支持矩阵。

adapter/第三方插件必须声明版本范围、数据权限、能力/未知项、资源与信任需求，并通过公开契约测试集。插件注册不等于安全审计背书。社区报告先脱敏，再由贡献者选择是否公开；禁止默认上传用户策略以换取支持。

v1 后托管服务、团队权限、账单和多租户隔离分别立项，必须有用户需求、单位经济测量和运维资源。按月记录支持、依赖升级与外部案例排错占总可用净工程容量的比例；连续两个月超过25%且挤占核心交付时冻结新集成、缩小支持矩阵。每Sprint15h质量预算还包含正常测试和评审，不能全部视为额外支持余量。
