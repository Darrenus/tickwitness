# 0.1.0a1 技术预览候选

状态：**待 owner 接受与发行**。这是 S04-03 / [Issue #12](https://github.com/Darrenus/tickwitness/issues/12) 的候选发布记录，不声称 release tag、GitHub Release 或 PyPI 包已经存在。版本号采用 `0.1.0a1`，范围是受限技术预览，不是 GA、市场采用或收益有效性认证。

## 本候选交付什么

可安装 CLI 把原创合成行情的 `import → v2 freeze → budgeted replay → export → offline verify` 接成完整链路。支持 EUR/USD、单个内置 post-only 限价买单、接收顺序时钟、MARGIN/NETTING 和最后观测 bid 估值。独立 verifier 复算输入绑定、固定费用数值模型、账务及 scoped claim observation。

v1 声明继续不可执行；失败/超时/中断不返还 per-protocol attempt 预算。导出包可以搬离原目录，不依赖原 catalog、native 环境或 attempt ledger 核验。原子 no-replace 发布、配额、no-follow 读取及损坏负例属于本次工程范围；不承诺真实断电认证或恶意 owner 沙箱。

安装与完整合成流程见[快速开始](../quickstart.md)，任务级矩阵及升级回退见[支持范围](../support.md)，详细语义见[证据工作流](../evidence-workflow.md)。

## 已知限制

- 没有用户策略源码执行、确认集解封、反例搜索 finding、观测相容队列证书、自动最小化、checkpoint 恢复或实时交易。
- 最后 bid marked PnL 不是可实现清仓收益；没有退出深度、冲击和退出费用。费用数值模式存在歧义时，估值和 claim 保持未知。
- `completed`、`eligible`、`satisfied` 分开；incomplete 或失败不能升级为研究通过。
- 离线验证不重新执行 native 撮合、不认证作者/日志来源、不检查外部确认集、不证明全部历史尝试已经登记。自洽合成数据不能被表述成真实市场证据。
- 当前是可信 owner 模式。子进程不是任意恶意代码或宿主资源的安全沙箱；不提供广泛稳定公共 SDK、HTTP/MCP/UI、GPU 后端或生产容量保证。
- 真实访谈、外部采用和独立人类领域复核仍有缺口；AI 交叉审查与自动回归不替代这些证据。Issue #12 的完成不自动关闭其他开放故事或全部 Sprint 门槛。

## 发布门与操作交接

维护者在远端 CI 执行打包与核验，本次不要求使用用户本机计算。候选准备接口为：

```sh
python scripts/prepare_preview.py --root . --dist dist
```

此处 Python 为远端固定环境的解释器。脚本要求干净 Git checkout 和已构建的发行物，生成 `preview-manifest.json` 与 `SHA256SUMS`；manifest 绑定真实 commit、`uv.lock` hash、wheel/sdist hash。它不构造作者签名，也不能仅因脚本成功就宣称测试通过。实际输出位置与完整 CI 命令以[准备脚本](../../scripts/prepare_preview.py)和 [Engineering](../../.github/workflows/engineering.yml)为准。

`preview-artifacts` job 在原有 required jobs 成功后，对实际发行物进行独立 core/native wheel 验收，并上传 CI artifact；源码包中的样例也须参与安装后核验。CI artifact 不是 GitHub Release、release tag 或 PyPI 发布。运行链接、实际产物 hash 和上表逐项结果仍须填写；脚本与 workflow 的存在不代表这一候选已完成执行。

发行顺序应满足：

1. 固定候选 commit 和 `0.1.0a1` metadata/lock，全部 required checks 在该 commit 通过；失败或取消不能记为成功。
2. 从干净 checkout 构建 wheel/sdist，检查发行物内容、版本与许可材料，保存文件 SHA-256；安装并测试实际产物，不能仅验证 editable 源码。
3. 核心安装离线验证固定样例；原生安装执行完整链路与迁移核验，同时保留确认集拒绝、缺依赖消费预算、篡改与失败边界记录。现有自动化见 [Engineering](../../.github/workflows/engineering.yml)、[wheel smoke](../../scripts/smoke_distribution.py)、[evidence smoke](../../scripts/smoke_evidence.py)。
4. 填齐上表和支持/已知限制，owner 阅读差异并接受后，再决定创建预览 tag/发行。使用已通过核验的相同字节，避免发行时另构建未验证产物。
5. 对外提供固定版本取得方式、校验清单、源 commit 与样例来源；仅以受支持组合和已实际执行的证据作说明。不以 star、测试数或 AI 审查声称用户采用。

候选源码包包含构建/开发所需的锁文件、Makefile、脚本、文档、研究记录和原创样例，实际文件闭包须通过候选制品检查。`prepare_preview.py` 的 commit 绑定需要 Git 元数据，不能把从 sdist 解出的目录误当作干净 Git checkout。wheel 不附带 `examples/`，必须同时保留版本匹配的源码包或样例取得路径。若改变源码包内容或发行渠道，需同步安装说明和实际 CI 验收。

## 升级与回退

预览无自动迁移承诺。安装新候选使用独立环境和工作目录，保留旧 wheel、原数据、完整 catalog/CAS、registry/ledger 与导出 bundle。不覆盖旧对象或重写已注册协议；不支持的格式明确拒绝。回退使用旧版本环境和匹配备份，不能假设旧版理解新格式。详细步骤见[支持政策](../support.md#兼容升级与回退)。
