## 1. 要讨论的研究命题

草案命题：在指定合成观测、固定策略、费用与期末估值规则下，该策略的期末净标记损益 `net_marked_pnl > 0`。

这里的“净”只包括草案明确规定的成交费用；“标记损益”包含以固定期末参考价估值的持仓，不表示已经按该价格平仓，也不等于可实现收益。命题没有声称未来赚钱、现实成交已知或统计显著。

首先讨论的是：**同一份 L2 观测，在列明的回放近似与允许的队列解释内，是否可能使命题真假不同？** 这与主动增加接收延迟后的压力测试分开。

## 3. 用于手算的合成条件

- 价格使用整数 ticks，数量使用整数 lots；每 tick 每 lot 的计价单位为 1，均为虚构单位。
- 策略只提交一次限价买单：价格 100 ticks、数量 1 lot；不再撤单或追加订单。
- 初始现金可覆盖订单，初始持仓为零；成交时收取固定费用 1 个计价单位，未成交不收费。没有融资、资金费、返佣或其他费用。
- 期末冻结参考价为 102 ticks，仅供期末 evaluator 估值，不允许提前提供给策略。净标记损益为 `持仓 × 102 − 买入支出 − 已发生费用`。
- 为了讨论队列，按 FIFO 和小订单不改变历史行情的 market-replay 近似设计。公开 L2 观测不包含逐订单身份；新加入的虚拟策略订单不修改录制的外部市场流。
- 最后一条是明确建模近似，不是事实证明。即使反例在该近似内成立，也不能声称真实提交自己的订单后市场仍完全相同；toy case 的规模也不能用于校准现实冲击。
- 事件时间以相对偏移表示，尚未指定真实日期、交易所或本地接收时间。后续 fixture 要单独给出稳定序列、接收可用性与事件 tie-break 规则；缺字段时不能默认为已测得。

## 4. 正例：预期应发现模型集合内的真假分歧

下面是**原始fixture的手算设计**，不是运行日志。S2执行结果与未通过门另见补测报告，不能用本表替代实际输出。

| 合成步骤 | 可见的外部 L2 信息 | 在草案中的解释 |
| --- | --- | --- |
| A | 100 ticks 买价上有 1,000 lots | 策略虚拟买单随后加入，其前方可见量为 1,000 |
| B | 同价外部量增加 1,000 lots，总量 2,000 | 新增外部量按草案 FIFO 规则在策略之后 |
| C | 同价外部量减少 1,000，且该步骤没有成交 | L2 不含撤单身份；可能从策略前方撤，也可能从后方撤 |
| D | 同价发生 1 lot 主动卖出成交 | 是否轮到策略订单，取决于 C 中撤单的位置解释 |
| E | 期末参考价固定为 102 | 只用于 evaluator 期末标记估值 |

两种允许解释都必须通过未来的约束验证和重放，才能成为有效见证：

| 队列解释 | 手算期望：步骤 D 前排队量 | 手算期望：虚拟成交与损益 | 命题 `net_marked_pnl > 0` |
| --- | --- | --- | --- |
| Q-front：C 撤去前方 1,000 lots | 0 | 买入 1；`102 − 100 − 1 = +1` | true |
| Q-back：C 撤去后方 1,000 lots | 1,000 | 未成交，持仓与费用均为 0，损益 0 | false |

这是命题真假分歧，不是必须一正一负的收益比较。若实际引擎的撮合规则、聚合消息语义或费用处理不支持上述解释，不能硬填期望输出；应修改 fixture 或记录不支持。

预期标签只有在两种场景都属于 `OBSERVATION_COMPATIBLE`、都可行、都独立复验且命题真假相反时，才可以是 `NOT_IDENTIFIABLE_WITHIN_MODEL`。该标签只针对列明观测、约束和回放近似，不推广到整个市场。

## 5. 负例：不应制造队列歧义

构造一个独立对照 fixture：与 A/B 的起始队列规则相同，**没有步骤 C 的撤单**；步骤 D 改为同价 1,001 lots 的主动卖出。外部量 2,000 足以支持该录制成交量；在已声明的小订单回放近似中，策略前方量 1,000 被消耗后，1 lot 虚拟订单在两种队列配置下都应成交。

因此，手算期望均为 `+1`，命题均为 true。有限两模型检查不应凭不同配置名称生成不可识别结论。假如两配置实际使用了不同费用、估值或事件顺序，应先判为不等价对照，而不是把差异归因给撤单位置。

S2独立probe已生成并运行这个负例的内置模型变体，原始输出见补测；它仍未获正式产品协议验收。日后必须给它独立的数据/协议身份，禁止与正例混成市场样本或据此推断真实误报率。

## 6. 未知例：不能完成协议的输入

如果待执行协议要求按本地接收时间决定可见数据，但输入只有交易所时间、没有可靠接收时间；或者关键快照/序列缺失，无法重建决策区间，那么本案例不能满足前置条件。

预期应保留未知或返回 `INSUFFICIENT_EVIDENCE` / 明确的输入错误，具体由失败原因决定。不能拿交易所时间代填接收时间，不能靠后来的快照补出丢失路径，也不能将执行失败记录为 `NO_COUNTEREXAMPLE_FOUND`。

虽然独立probe已有执行产物，正式adapter、冻结协议与双见证可行性验收仍未完成，**草案仍处于未验证状态**，不能因为纸面预期或模型敏感性翻转而登记成产品已发现反例。

## 7. 另立协议：新增接收延迟压力

额外延迟属于 `COUNTERFACTUAL_STRESS`。可先讨论 `δ ∈ {0, 5, 20} ms` 的离散范围，但这些只是待试验的人为参数，没有现实校准依据。

后续 fixture 必须明确：被延迟的是哪类接收消息、何时对策略可用、订单延迟是否保持不变、同流序列如何保持，以及决策是否重新计算。不能直接在完成的交易表上移动时间或调费用，冒充重新回放。

δ 为零应与基线等价；δ 为正不得让任何消息更早可见。具体是否改变订单与损益目前未知，不能预填“增加 5 ms 就失败”。即使未来结果翻转，也只能说在额外压力下敏感，不能据此标记“同一历史的可行解释已经矛盾”。

本草案第一步不同时搜索队列和新增延迟，避免混淆结论来源。若日后做组合压力，需要新协议、单独场景类型与预算账本。

## 8. 术语卡

| 术语 | 在本案例中的含义 | 不能推断成什么 |
| --- | --- | --- |
| 观测 | 实际记录或生成并保存的消息及来源 | 文档中的设计表不等于已存在数据 |
| L2 | 价格档位聚合数量 | 全部订单身份、真实撤单位置或真实自身队列 |
| 观测相容解释 | 在列明证据、约束与模型近似内未被排除的解释 | 无条件真实世界、唯一真实撮合路径 |
| 压力情景 | 主动增加的故障或执行条件 | 对既有历史的事实还原 |
| 声明 / Claim | 明确可被判 true/false 的研究命题 | 一张漂亮收益图或模糊的“策略有效” |
| 协议 / Protocol | 数据、策略、假设、判定、版本与预算的固定规则 | 可以看完结果再原地修改的配置 |
| 见证 / Witness | 可行且可重放的具体结论分歧案例 | 搜索器未经验证的候选或文字解释 |
| 不可唯一确定 | 两个有效观测相容解释使命题真假不同 | 两个随意模型收益不同，或市场没有规律 |
| 未发现反例 | 在披露的场景与预算内未找到有效见证 | 已证明稳健、真实收益下界 |
| 独立复验 | 在新环境按冻结输入重算并校验 | 作者读一遍结果或 LLM 表示同意 |
| 最简见证 | 仅按声明的算子和邻域简化 | 全局最小，除非有额外可检查证明 |

## 9. 从草案到执行所需证据

1. 维护者复核命题、手算、队列可行性和 market-replay 近似；记录反对意见。

5. 才能冻结真实协议、登记 trial、运行候选并封存/复验；纸面数值不能写成实测成果。
