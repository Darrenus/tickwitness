## 1. 本轮需要验证什么

优先观察过去 90 天内的真实行为：研究者是否经历过执行假设、行情缺陷或复现困难导致研究决定变化；目前怎样解决；需要付出多少主动操作与协助时间；现有脚本是否已经足够好。

第一轮目标为 S1 完成 2–3 次、S1–S2 累计 3–4 次有效近期痛点访谈；到 S6 再根据招募与实际容量争取累计 8–12 次。它们是目标，不是结果，也不代表任何人已经预约。招募、准备、整理均纳入故事预算，不从日常质量预算隐式补工时。

受访者优先条件：最近实际运行过自己的研究或审查过他人回测；能描述具体流程与失败经历；能够展示非敏感部分，或愿意只口述。独立研究者、研究工程师和评审者均可。没有相关痛点、已有足够好工具、拒绝提供案例，都是有效反对证据。

以下文字尚未发送，发送对象、渠道与社区规则需要维护者自行确认。文案不应暗示产品已经实现，也不要求参与者公开策略。

## 3. 同意与隐私：开场逐项确认

建议口头开场：

> 今天目的是理解你的工作，不评判策略好坏。你可以不回答、只口述或随时结束。我默认只做必要的文字笔记，不录音。原始身份、联系方式和笔记不会进入公开仓库；如要保存屏幕资料、引用原话或公开案例，我会单独向你确认范围。哪些信息不能记录或需要立即删除，请直接指出。

需要记录的同意字段是空模板，不能预先替参与者勾选：

| 项目 | 待记录值 | 规则 |
| --- | --- | --- |
| 参与本次访谈 | 待参与者确认 | 不同意则结束，不生成有效访谈记录 |
| 必要文字笔记 | 待确认 | 可以只保留经参与者确认的匿名摘要 |
| 录音/录屏 | 默认不启用；如有需求另问 | 不能把同意访谈视为同意录制 |
| 保存某份截图/文件 | 默认不保存；逐项询问 | 参与者需有权提供；不要求上传原始策略或行情 |
| 匿名化摘要内部使用 | 待确认 | 与公开使用分开；公开仓库不等于内部空间 |
| 原话或案例公开引用 | 默认不允许；另行确认 | 确认具体文本、归属方式和材料范围 |
| 后续联系 | 待确认 | 访谈不自动授权再次联系 |
| 撤回/删除联系办法 | 由维护者给出实际可用渠道 | 不填不存在的邮箱或假承诺 |

实际姓名、联系方式、原始笔记和音视频**不得写入这个 public repo**。如后续访谈确实开展，应由维护者另存至受控私有位置并核实访问权限；不能只因目录名含 private 就假设 Git 已忽略。公开文件只能保存经确认可发布的匿名汇总或合成模板。

建议最小保留规则：联系方式仅用于已同意的安排；原始资料建议访谈后 90 天内复核删除，确需继续保留时重新说明用途；无必要的敏感内容立即删除。实际保留期限与参与者约定后记录，不把此建议当成已取得的同意。公开材料发布前说明已经公开的副本可能无法完全回收，避免承诺无法做到的彻底删除。

## 4. 30–45 分钟近期行为提纲

| 时间 | 目标 | 问题与追问 |
| --- | --- | --- |
| 0–5 分钟 | 范围与同意 | 今天哪些内容可以记录？可以只口述。确认最近是否有实际研究/评审经历 |
| 5–10 分钟 | 锚定一项近期任务 | 请选过去 90 天最近一次完成或放弃的研究。最后需要决定什么？用了什么证据？ |
| 10–22 分钟 | 还原实际流程 | 从拿到数据到作决定，依次用了哪些工具？哪一步需要重跑或请别人帮忙？能展示非敏感操作时由参与者自行选择 |
| 22–30 分钟 | 假设变化与排错成本 | 最近一次改队列、延迟、费用或清洗规则发生了什么？若没有也请直接说明。怎样确定变化来源？主动操作、计算等待、协助时间分别多少？ |
| 30–36 分钟 | 审阅与交接 | 当时怎样交给别人复查？对方能独立跑吗？什么资料缺失？现有脚本能否已经解决？ |
| 36–41 分钟 | 最后才展示草案 | 展示 [合成声明草案](claim-draft-001.md)，先声明未实现、未验证。请对方用自己的话解释“未发现”“证据不足”和“观测相容/新增压力”的区别 |
| 41–45 分钟 | 反对证据与下一步 | 哪一步增加负担？什么情况下你不会用？如果愿意验证，具体是哪一个下次任务、哪些输入可留在本地？是否允许后续联系？ |

30 分钟版本保留同意与近期任务，减少草案展示时间；不能把问题访谈变成 25 分钟产品推销。参与者没有相应经历时，不诱导编造故事；按“不符合本轮近期行为样本”记录，但保留有用的反对证据。

追问要区分事实与估计：“这个时长有日志还是回忆估计？”“最后实际采取了什么行动？”“能否描述一个最近的具体例子？”不要用“这是不是很痛”“这个肯定有帮助吧”引导答案。

## 6. 私有证据登记空模板

以下模板尚未填写。实际记录置于受控私有位置；公开仓库只保留模板。

```text
record_status: EMPTY_TEMPLATE
participant_id: <匿名 ID，不写姓名/公司>
interview_date_and_timezone: <待填>
role_and_eligibility: <角色、最近实际任务日期；避免可反推身份的细节>
consent_record: <同意范围、禁止保存项、保留期限、后续联系许可>
recent_task: <实际目标、触发事件、现有工具>
current_workflow: <参与者实际描述的步骤>
pain_or_no_pain: <具体后果；没有痛点同样记录>
existing_alternative: <现有脚本/工具/人工方法以及是否已足够好>
active_time: <值、单位、测量/回忆估计/未知>
compute_wait_time: <值、单位、测量/回忆估计/未知>
support_time: <值、单位、测量/回忆估计/未知>
evidence_items: <每项注明原话/可观察制品/参与者估计/维护者解释>
objections: <原话与解释分开；不能只留赞同>
case_commitment: <具体任务与准备行为；无承诺则填无>
next_contact_allowed: <是/否/未确认，不能预先代填>
public_use_allowed: <逐项范围，默认不允许>
unknowns_and_disconfirming_evidence: <待核对与反驳>
owner_interpretation: <假设更新，不冒充参与者原话>
decision_and_followup: <继续/缩小/停止/未知，理由和内部引用>
```

每条证据采用以下来源分类，不凭一句回答升级结论：

- `PARTICIPANT_REPORT`：参与者叙述，尚无独立制品核验。
- `ARTIFACT_OBSERVED`：当场看到的非敏感步骤/材料；记录同意范围与核验边界。
- `PARTICIPANT_ESTIMATE`：参与者估计的频率、耗时或成本。
- `OWNER_INTERPRETATION`：维护者归纳与产品判断。
- `UNKNOWN`：未问、未获同意或无法确认。

拒绝、未回复、未约成不算一次有效问题访谈，也不能被登记成“不需要产品”的确定证据；原因未知时保留未知。引导性演示后的一句“不错”也不算价值实现。

## 7. 必须保留的反对意见

访谈时主动给出表达反对的空间，检查但不预设以下可能性：

| 可能的反对证据 | 应追问什么 | 可能的决策 |
| --- | --- | --- |
| 现有脚本已经足够 | 请演示最近一次处理过程与交接成本 | 作为对照；考虑只提供 verifier/插件 |
| 所有范围都没有可信依据 | 哪种证据能够限定它？目前是否能取得？ | 先补证据，收缩判定范围 |
| 反例不影响任何研究行动 | 最后依什么继续或停止？ | 重新选择目标问题，不按“找到负收益”计成功 |
| 接入成本高于收益 | 要写多少适配代码、谁维护？ | 优先降低输入/接口成本，减少支持范围 |
| 模拟成交无法代表真实执行 | 需要哪些自有回报或逐订单数据？ | 明确模型边界，不能销售真实成交认证 |
| 不愿分享专有研究 | 能否只在本地运行或提供匿名摘要？ | 尊重拒绝；默认不收集策略 |
| 只是想要盈利信号 | 最近真正需要完成的任务是什么？ | 调整招募画像，不扩展成交易执行产品 |

这些是待检查的方向，尚无参与者给出这些回答。
