# ADR0044：执行信任边界与未启用隔离的明确合同

状态：S13-01冻结，2026-11-19 Asia/Singapore；文档决定待owner接受，受限隔离实现及独立安全复核尚未完成。

## 背景

owner已接受[PR113](https://github.com/Darrenus/tickwitness/pull/113)，真实merge `df10923663a3d3c09b5b917995fbb554da60ea40`。SDK与CLI已具备严格输入、冻结协议、原预算、独立结果复算、Job与部分资源控制，但这些不同层次的保证不能组合成对恶意代码、同UID进程或宿主owner的安全沙箱。旧目标架构的“只读worker／隔离／配额”和资格guard容易被抽离成已经实现的安全保证。

当前任意用户Python策略没有执行入口。`.py`源码冻结只读取、解析语法并绑定哈希；实际native路径运行已资格的内置profile。生产worker未清洗继承环境，也未实现网络默认拒绝、独立UID、内存／PID／总磁盘隔离。现有CPU／单文件／FD上限、固定入场deadline、group终止及owned scratch回收仍有各自真实价值与边界，不应被抹去，也不能扩大成整个宿主的强制保障。

## 决定

先冻结[Execution trust v1](../contracts/execution-trust-v1.md)，用三个**仅文档标签**区分支持状态：

1. M0可信本地：仅现有已资格内置profile，owner、根及祖先、解释器／依赖／宿主可信；远端单owner机器也可采用此信任模型。
2. M1受限单机隔离：规范要求集合，当前未实现／未资格／关闭；具体环境、机制、数字限额未选定时不能启用，不提供虚构mode flag或自动降级到M0运行不可信代码。
3. M2不支持需要独立用户／租户身份、权限和数据边界的托管／协作服务：未具备相应秘密与资源隔离、服务及运维资格；自托管或普通容器不会自动满足门槛。同一可信owner边界内的人工协助或授权离线包交换不因此成为多租户支持。

合同列出资产、信任基础、文件／环境／网络／资源矩阵、当前代码与测试锚点、T01–T10威胁、未知／拒绝语义及后续启用证据。独立安全复核与外部真人复验分别记录，不把CI、AI或owner接受计作任一真人认证。

安全模式不能新增研究权限、隐藏重跑或更换原预算身份。实际重跑使用原协议的新槽；已提交结果只复核／ACK；失败、中断和未知状态不退款。确认访问、判定和资源观测保持各自合同，哈希不认证作者或全部历史。

## 影响与验证

本故事为原10h，S13仍10+16+8=34h，持续质量容量不变，无实际工时声明。先推送本合同／ADR，再对齐support、SECURITY、目标架构、入口及Sprint追踪。S13-02负责原16h内的一个有界环境实现与负例；S13-03负责原8h复核准备／降级与真实采用观察。无法建立边界时维持M0范围，不扩预算、改名通过或提前启用不可信托管。

不新增domain aggregate、SDK方法、schema、CLI mode selector、依赖、工作流或sandbox实现。文档更正按[DoD](../planning/working-agreement.md)使用实际既有远端检查与静态一致性审阅，不制造镜像文档的无价值测试，也不把文档／旧测试成功称为本轮攻击资格。

所有项目执行仍在远端CPU。外部真人0/0/PENDING、#24 OPEN、自有案例空登记及UNKNOWN联系／回复保持；原5/8/11、golden、PR94与既有封存不重置。本ADR不授权自动合并、发行、HTTP/MCP、GPU或外发联系。
