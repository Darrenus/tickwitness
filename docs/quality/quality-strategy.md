# TickWitness 质量与研究有效性策略

状态：Proposed，2026-10-25。所有数值是初始验收目标，尚无实测基线；S1 比较候选引擎、S2 固定引擎版本，S3 完成 adapter 后建立可比 benchmark 环境和基线，再按证据调整并记录理由。

## 质量目标

首要目标是结论语义正确、数据与制品可追溯、失败可见、相同条件下可复现。吞吐、搜索速度和界面响应在此基础上优化。实现完成、性能达标、用户实际采用分开验收。

每次结果至少绑定：claim/protocol 哈希、原始输入及数据许可引用、规范化和时间语义版本、feature/strategy/code 版本、引擎/adapter 版本、队列/费用/估值规则、场景集合及其类别、搜索预算与 seeds、运行环境、结果 schema、证据索引及停止原因。哈希验证内容一致性，不能证明数据真实或模型正确。

## 研究有效性规则

| 规则 ID | 必须保持的语义 | 必需验证 |
| --- | --- | --- |
| Q-01 | 事件时间、接收时间与决策时可用时间有独立含义 | 迟到消息、跨流时间不确定、时钟跳变夹具 |
| Q-02 | 缺口后重同步恢复状态，不恢复缺失的历史路径 | 缺口跨决策区间时拒绝精确回放或显式降级 |
| Q-03 | L2 队列解释是模型；不能标记为真实成交 | 同一观测、两种允许解释、相反判定案例 |
| Q-04 | 观测相容解释与新增故障压力场景分开 | 错误类别组合必须拒绝，报告并列呈现 |
| Q-05 | 有限搜索无反例不是稳健证明 | 零预算、提前取消、未覆盖场景均不得显示已证明 |
| Q-06 | witness 不得依赖非法序列、无效快照或决策后数据 | 独立 replay verifier 重建并复算差异 |
| Q-07 | 最简/最小声明与算法实际保证一致 | 记录缩减算子、邻域和未搜索范围 |
| Q-08 | 冻结后协议不可原地修改 | 修改必须生成新版本及新的 trial 记录 |
| Q-09 | 全部尝试纳入可见实验账本 | 失败、取消、重复和参数变体均有记录 |
| Q-10 | 统计判定与执行模型不确定性分别报告 | 场景范围不可输出为置信区间 |
| Q-11 | 改变场景后策略重新决策 | 不能只在已完成的交易清单上改手续费冒充全量回放 |
| Q-12 | 无法检查的数据、权限或语义不得默认成功 | unsupported/incomplete/error 结果与科学判定分开 |

对于 DSR、FDR、bootstrap 等，先给清楚待检验声明、样本依赖结构、试验总体与选择过程，再选择实现。冻结 test 不允许反复看分数调策略；反例发现用开发/验证窗口，最终评估使用独立案例和新采集窗口。无法获取真实自身成交时，不能以一个模拟器校准另一个模拟器后宣称验证真实 fill。

## 测试分层与门禁

| 层级 | 范围 | 执行频率 | 初始门禁 |
| --- | --- | --- | --- |
| Domain 单测 | 值对象、状态机、不变量、判定边界 | 每次 PR | 关键规则正/负/未知三类案例全部通过 |
| 属性与变形测试 | 金额守恒、合法序列、前缀不看未来、seed 稳定性 | 每次 PR，较大语料 nightly | 失败保存 seed 与缩减制品；无未解释失败 |
| Adapter 契约 | 数据映射、费用舍入、订单生命周期、引擎能力声明 | adapter 变更及发布 | 固定夹具通过，unsupported 不静默补齐 |
| 差分验证 | 手算参考与已选引擎；匹配语义后的结果 | 核心/引擎变更 | 差异必须归因，不能用宽容差掩盖语义冲突 |
| 集成 | 文件/CAS/catalog、事务、jobs、API/MCP | PR 选取，nightly 全量 | crash/retry/cancel 幂等，无伪成功证据 |
| 端到端 | 导入→冻结→搜索→witness→独立复验 | 关键 PR/发布 | 干净环境离线可复验已授权夹具 |
| 安全与供应链 | 路径越界、压缩包、恶意代码、依赖、镜像 | PR 与发行 | P0/P1 未解决不发布相关能力 |
| 运维 | 断电恢复、备份恢复、磁盘满、版本升级 | 每阶段 gate | 实际演练记录，不以 runbook 存在代替通过 |

领域包初始目标为分支覆盖率 ≥90%，整体代码行覆盖率 ≥80%；只有实现后才启用对应门禁。覆盖率不能替代规则矩阵。关键判定和状态机选用 mutation testing，基线建立后以 ≥80% 有效变异杀死率为初始目标；equivalent mutations 需要有记录。资源限制、超时和正常 unknown 情况也必须有负例。

## 基准语料与实验设计

建立四类语料：手工可检查微型案例；有已知真值的合成缺陷与干净对照；有合法权利的真实行情切片；独立贡献者提交且完成脱敏的外部案例。自建缺陷集只证明覆盖已设计缺陷，不能单独支持泛化能力宣传。

比较固定 sweep、随机搜索和 TickWitness 搜索时，冻结数据、评价函数、可行场景空间与运行预算；采用共同 seeds/重复次数，报告失败率与置信区间。评测集不进入启发式调参循环；正负例、缺陷家族与市场日期按预注册拆分。初期至少 20 个可手查案例和两个简单策略；更大测试集由后续 Sprint 扩充。

| 指标 | 定义 | 使用限制 |
| --- | --- | --- |
| witness 有效率 | 独立 verifier 接受的 witness / 搜索输出 witness | 不代表真实世界成交已被证明 |
| 检出率与误报率 | 已知缺陷/干净案例上的检测结果 | 按缺陷家族、数据源分组，给分母与区间 |
| time-to-counterexample | 同预算与硬件下首次有效反例时间 | 未找到案例作为 censored/未找到单列 |
| 缩减效果 | 必要事件数、片段长度、复验时间相对原案例的变化 | 必须仍保持有效序列和相同失败条件 |
| 重现成功率 | 不参与开发的人按文档成功复验 / 尝试复验人数 | 同时记录环境与失败原因 |
| 用户价值 | 外部工作流中节省定位时间、发现额外问题 | 从真实用户实验获取，不从合成数据推断 |

不得为了达到单一 recall 目标，把正常无法判断当成缺陷命中。v1 需要固定 held-out corpus 及外部案例记录，目标与是否达标在 release checklist 中分开列示。

## 性能与可靠性验收预算

参考环境拟为 4 CPU、16GiB RAM、SSD；输入固定为 100 万条规范化事件、两策略、十个场景的可授权语料，容器/解释器/引擎版本和并发度全部固定。S2 的候选引擎测量仅作为探索记录，S3 在完整 adapter 上建立可比基线；TickWitness 单次 replay 的额外开销初始目标 ≤20%，只有双方工作量和语义一致时才比较。未测前不发布 events/s 数字。

元数据与 job 状态查询在 1 万条 job 元数据、4 并发下 p95 <500ms；长任务提交 <1s 返回 job ID，不承诺搜索一秒完成。取消请求后 5s 内调度器发出停止，worker 硬超时规则及外部引擎响应分别测量。峰值内存、临时磁盘、队列积压和预算耗尽必须有界且可观察。

固定硬件同输入性能回退 >15% 触发复核，确认不是噪声后才能阻止发行；正确性修复可接受已记录的性能代价。发布报告列 raw samples 与方法，不只贴最优单次数字。

## 发布质量门

| 发布 | 必需证据 |
| --- | --- |
| v0.1 / 内部可用 | 一个完整可信代码路径；精确声明支持输入；失败语义；离线复验与开发安装文档 |
| Alpha / S8 | 受约束搜索、合法 witness、已知缺陷集和干净对照；同步失败可见且制品原子提交；至少一个外部复验尝试有记录。完整持久 jobs 恢复/取消在 S10 的0.3门验收 |
| Beta / S16 | 至少3位外部用户激活、其中至少2位有限协助完成；外部案例与盲读；安全边界明确；最小旧格式拒绝/原件保留及备份恢复通过；已有性能基线。S18/S19扩充分版本迁移与全量运维演练 |
| v1.0 | roadmap/产品门全部通过；至少2位满30天窗口的外部用户自发完成第二个研究；核心支持矩阵、兼容性与弃用政策；独立复现；关键漏洞无未缓解项；恢复/升级/回滚演练；维护者能承担支持负载 |

每个 gate 输出 checklist、制品链接、未通过项、owner 和决定；“时间到了”不能跳过 gate。核心 v1 必须交付 CLI/SDK、数据与回放契约、搜索、证据/独立核验及相应运维；HTTP/MCP/UI 根据采用需求且各自通过 gate 后作为可选入口发布，未达标可以延后，不能扩大宣传范围或拖低核心验收要求。
