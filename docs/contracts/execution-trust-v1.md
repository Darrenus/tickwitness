## Authority, assets and trust boundaries

This contract belongs to the infrastructure/operations boundary. Domain/application services retain the frozen protocol, attempt reservation, confirmation exposure, Job state, publication and finding rules. A worker computes a bounded result; the coordinator validates/adjudicates it. Neither a mode label, Agent proposal, runtime telemetry nor a successful process exit creates a research finding, permission or extra attempt. No new domain aggregate, SDK method, flag or persistent field is introduced.

| Asset | Why it matters | Authority that must remain separate |
| --- | --- | --- |
| Raw/normalized data, time evidence and manifests | Missing/altered inputs change the research scope | Import validation is not feed provenance or proof that unknown receive time is known |
| Strategy bytes, dependencies and built-in adapter | Code can acquire the host's execution permissions | Source registration/AST parsing is not execution approval or supply-chain authentication |
| Protocol, rubric, seeds, scope and original attempt ledger | Reconfiguration or hidden retries can change the conclusion | Existing frozen identities, reservations and explicit followups remain authoritative |
| Confirmation data and exposure records | Reopening data must not restore an unseen state | Application denial is not secrecy from the host owner |
| Catalog, Job journal, final CAS/bundles and indexes | Forged/partial output must not become an accepted result | Coordinator validation/publication is not an OS barrier against its own UID |
| Host files, credentials, sockets, network and other workloads | A malicious dependency/task could read, modify or exhaust them | The current process has host-granted permissions; a narrow IPC payload does not revoke them |
| Temporary files, logs and diagnostics | Cleanup or disclosure can damage evidence or expose private data | Only owned, safely reclaimable scratch may be removed; uncertainty preserves diagnostics |

The local owner, configured input/storage roots and their ancestors, interpreter, OS/kernel, dependencies and coordinator are trusted for the current mode. Authorized input **bytes** may still be malformed and require bounded parsing. Do not execute unknown strategies/plugins, accept unreviewed dependencies or delegate unrestricted shell/file access to an Agent and then claim these are protected by TickWitness.

Data suppliers, imported bundles and Agent/tool text do not acquire authority merely by passing a hash check. A hostile host owner, compromised coordinator/kernel, fully rewritten local history, unreviewed native dependency, cross-user attacker and malicious code containment are outside the present supported guarantee. A hash-bound closure detects discrepancies relative to its supplied anchors; it does not authenticate the producer or prevent an owner replacing all anchors. See [SECURITY](../../SECURITY.md) and the [domain trust boundaries](../architecture/domain-model.md).

## Three-mode matrix

M0/M1/M2 are documentation labels, not existing CLI/SDK options. Deployment location is distinct from trust: one trusted owner using SSH on a supported remote machine is still M0. People may exchange authorized offline bundles or assist inside one chosen trust domain; that does not supply independent per-user permissions or tenant isolation. Remote CI success, a VM, a container, Colab or a rented GPU does not establish M1 or hosted support. Supported OS/Python/filesystem combinations remain only those in the [versioned support matrix](../support.md).

| Mode and current status | Files, environment and identity | Network | Resources and known gaps |
| --- | --- | --- | --- |
| **M0 TRUSTED_LOCAL — current supported trust boundary**, only within existing qualified built-in profiles | APIs constrain their own inputs and owned outputs. Root/ancestor configuration and same-UID host permissions remain trusted. There is no mount/chroot/UID barrier or environment allowlist. User `.py` is registered as bounded syntax/hash-bound data, not executed; arbitrary strategies remain unsupported | No production default-deny egress guarantee. No HTTP/MCP listener is supplied. Absence of a listener or a built-in profile's lack of network need is not a network policy | Existing protocol/campaign/optional Job controls apply in their documented scope. No guaranteed whole-tree RAM/PID/CPU, total disk/inode quota, escaped-descendant containment or host confidentiality |
| **M1 RESTRICTED_SINGLE_HOST — requirements only; unimplemented, unqualified, disabled** | Future selected profile must isolate the execution identity and file view; immutable read-only inputs/TCB; only private quota-bound scratch writable; no secrets, home, host sockets/devices, control files or sensitive mounts; explicit minimal environment/FDs | OS-enforced default deny, including egress, DNS, loopback/IPv6 and inherited socket routes under that profile; only explicitly specified non-network IPC to the trusted coordinator | Must declare and enforce subtree CPU/time, memory, PID/process expansion, FD and aggregate writable-storage/inode limits, plus stop/reclaim semantics. Mechanism, numeric values, OS/image/kernel/filesystem profile are **NOT_SELECTED** here; missing selection/control/evidence keeps M1 unavailable |
| **M2 HOSTED_UNSUPPORTED — unsupported**; includes untrusted hosted tasks, collaboration requiring independent user/tenant permissions, and public/multi-tenant service | No current tenant identity/ownership/authorization, cross-tenant data or secret isolation, service administration or hostile-coordinator guarantee. Self-hosting does not supply these | No qualified remote listener, authentication/TLS/rate-limit/revocation/egress boundary | No tenant-wide quotas, scheduling isolation or operational/security qualification. A container or passing M1 test would not by itself supply them; separate scope, service threat model and external review required |

M1 qualification must name concrete mechanisms and numeric units before enabling anything. This document deliberately does not invent safe RAM/PID/disk defaults without an implemented reference environment. Future unavailable-mode admission must stop explicitly before worker launch/research reservation, with no silent M0 fallback. There is currently no mode selector to activate M1/M2; registering a source, setting a scalar parameter or changing an execution flag cannot create one. M1 work does not automatically add arbitrary strategy execution, another adapter or a service endpoint.

## Current controls and their exact limits

| Current control | Actual scope | What it does not establish |
| --- | --- | --- |
| [Safe file input](../../src/tickwitness/infrastructure/safe_input.py), [negative cases](../../tests/infrastructure/test_safe_input.py) | Relative paths, formats/depth, dirfd/no-follow opens, regular-file and byte/metadata-change checks within the trusted-root boundary | No `st_nlink`/owner isolation; no defense against a malicious root ancestor, same-UID process or host owner; no blanket safety for every filesystem |
| [Source registration](../../src/tickwitness/application/research.py), [SDK](../../src/tickwitness/sdk.py), [source tests](../../tests/application/test_research.py) | SDK freeze reads bounded request64KiB/source256KiB; the application parses UTF-8/Python3.12 syntax and hashes/seals source. Sentinel source containing `raise` is registered without execution | No `exec`/import dispatch of that submitted source. The [native adapter](../../src/tickwitness/infrastructure/nautilus_replay.py) uses the supported built-in strategy, not an arbitrary Python strategy |
| [Native request](../../src/tickwitness/domain/jobs/native_requests.py), [worker](../../src/tickwitness/infrastructure/native_job_worker.py) | Narrow versioned data, frozen spec/intent/attempt/deadline; no Catalog/ledger path, pickle, plugin or user-source execution payload | Path omission and coordinator-only logical publication do not make host files unreachable to a same-UID process |
| [Job controls](job-controls-v1.md), [bootstrap](../../src/tickwitness/infrastructure/job_control_bootstrap.py) | For an opted-in Job, immutable defaults:120s admission window,60 worker CPU seconds,8MiB per file,128 FDs,5s cleanup grace. POSIX CPU/FSIZE/NOFILE hard/soft ceilings and disabled core dumps apply before project/native imports; unsupported requested ceilings are refused | Not defaults for every historical worker/command. No privilege drop, environment scrub, memory/PID controller or total-disk quota. CPU is the scoped process limit; FSIZE is per file, not all files combined |
| [Controlled runtime](../../src/tickwitness/infrastructure/job_control_runtime.py), [cleanup](../../src/tickwitness/infrastructure/job_control_workspace.py), [runtime tests](../../tests/infrastructure/test_job_control_runtime.py) | Fixed monotonic admission/publication deadline, owned scratch/session, limited inherited FDs, cooperative group TERM/KILL and stop/lock/seal/inode checks before bounded cleanup | No namespace/cgroup or hostile escaped-process guarantee. Synchronous checks/kernel IO/fsync can delay physical stop/confirmation; an admitted commit is not undone. Uncertain stop, live lifetime or replaced scratch preserves the directory |
| [Campaign budgets](campaign-budgets-v1.md), [resource guard](../../src/tickwitness/infrastructure/campaign_resource_guard.py) | Original persistent admission/managed-payload accounting, bounded IPC and execution deadline; uncertain publication poisons further admission | Not a whole CLI wall-time promise, block/inode/directory/host-disk quota, RAM/cache limit or tenant quota |
| [Observed resources](job-resources-v1.md) | Declared coordinator/compute accounting, terminal child usage and deleted-entry logical bytes; unavailable metrics remain unavailable | RSS is not a simultaneous whole-tree memory peak or enforced cap; logical deleted bytes are not physical space freed; no invented predicate count or cost calibration |
| [SDK qualification](sdk-compatibility-v1.md), [functional harness](../../scripts/smoke_sdk.py), [typing harness](../../scripts/check_sdk_typing.py) | Test-only socket/process/native-import guards and direct-call accounting: functional27 plus typing4 within original32/28/4 admissions,30s ordinary waits and original180s deadline | Not production egress enforcement, an OS PID/tree quota, malicious Python containment or a cleanup hard deadline. `-I`, monkeypatches and direct-child kill do not provide these guarantees |

The code does not supply an explicit scrubbed `env` in the relevant worker `Popen` calls; inherited host environment must be treated as exposed to trusted code. Python documents environment inheritance when `env` is omitted in [subprocess](https://docs.python.org/3.12/library/subprocess.html); its [resource documentation](https://docs.python.org/3.12/library/resource.html) distinguishes system-dependent process CPU, single-file and FD limits. These explain limits, not a qualification of a particular host. Linux [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html) is background for hierarchical resource controls, not a selected/implemented TickWitness profile or complete filesystem/network sandbox.

## Budget, outcome and uncertainty rules

All modes retain the **existing** protocol/Job/family identities and rules. This contract adds no global ledger or cross-protocol trial authentication. No mode change, environment replacement, name, retry or security test resets the original5/8/11 fixtures, frozen attempts/events/native wall limits, golden records or PR94 evidence. Actual authorized re-execution needs a new reservation from the same original budget; failed/interrupted/uncertain reservations are not refunded. A committed result is reverified/ACKed, not executed again. Unsupported control preflight must not manufacture a research attempt; later failure must retain any reservation already admitted by the existing contract.

Keep execution status, research findings and completeness separate. A containment test failure, timeout, cancellation, invalid input or unknown stop is not a counterexample to a market claim or a research pass. Missing OS/controller/profile evidence, skipped attacks and unavailable metrics remain **UNKNOWN / NOT_QUALIFIED**; no fabricated zero, safe-stop receipt, permission or successful coverage. Denying confirmation through an application does not establish host secrecy. See [Job controls](job-controls-v1.md), [resource observations](job-resources-v1.md) and [followups](job-followups-v1.md).

## Acceptance and enablement gates

S13-01 accepts a traceable model/matrix and honest support documentation, not implementation of M1/M2. Positive review case: an authorized M0 built-in workflow stays within existing qualified interfaces and original budget. Negative review case: freezing source, adding `execution_ready` in scalar parameters or using a subprocess/guard is not M1 admission. Unknown case: a missing profile/control/test or uncertain stop cannot be described as isolated or safe.

S13-02 retains its original16h to select one bounded reference environment and implement/measure its chosen controls against T01–T08. Its evidence must bind exact OS/kernel/runtime/image or binary digests, UID/capabilities, mounts/FDs/environment, network policy, numeric resource units/scope, original-budget links, attack inputs/outputs, independent host observations, cleanup and unresolved gaps. Missing capabilities must refuse admission; there is no automatic fallback to running untrusted code as M0. A narrow result cannot certify all containers, hosts or arbitrary strategies. If that budget cannot establish the required boundary, retain M0 and record the gap rather than silently expanding the story or weakening it.

S13-03 retains8h for attack/review preparation, capability downgrade and separate real-user activation/reuse evidence. Before opening an untrusted-code capability, seek independent security review of the actual selected scope as required by the [working agreement](../planning/working-agreement.md); AI self-review, CI and owner merge are not that independent review. Without sufficient review/evidence keep the untrusted capability unavailable. Hosted/collaborative service admission requires a separate threat model and explicit authorization; this Sprint does not create it. HTTP/MCP remain conditional S14-or-later work, not implied permission to expose a listener.

All project tests, builds, installs, formatting/type checks, native execution and future attack qualification for this work run remotely on GitHub Actions CPU or a separately authorized remote profile. Static documentation review is not an attack test. Do not add mock tests that merely repeat this table or execute hostile payloads on the owner's workstation. Record actual current-head CI separately; do not inherit old green checks or call them external human validation.
