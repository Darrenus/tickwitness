## Scope and reference authority

Only an exclusively owned LocalDatasetStore's `objects/sha256/HASH` orphan regular entries can be removed. Retain EVERY catalog dataset and EVERY valid physical manifest, including manifests not yet catalog-visible, plus all their referenced objects. Dataset retention does not delete manifests, Catalog rows, reservations/outcomes/intents, protocols, Job/control/resource records, bundles, preparations, exports or another store. Supported consumers refer to published dataset identities; preserving all manifest closures protects those references without reading research/Job bearer payloads. Direct unregistered references to orphan paths are outside the supported store contract and are not a global reachability guarantee.

DatasetStore and AttemptLedger share an `objects/sha256` layout. Unknown or mixed top-level entries, including ledger/registry/Job namespaces, block the ENTIRE plan. Root allowlist is catalog.sqlite3,objects,manifests; objects contains only sha256. Any SQLite WAL/SHM/journal sidecar blocks maintenance. Unknown/pending entries, unsafe aliases/symlinks/hardlinks, invalid manifests, missing referenced objects, mismatched declared sizes, invalid Catalog/schema or scan limits also block with no candidates. Never infer permission from age, low disk, resource telemetry or a missing index entry alone.

## Coordination and read footprint

All new DatasetStore constructors/readers/publishers acquire a shared, nonblocking flock on the opened root directory inode before opening SQLite or CAS. Publisher holds it through first CAS write, manifest installation and Catalog commit; readers hold it throughout their read. Maintenance holds an exclusive nonblocking lock on that SAME inode across planning or complete revalidation/deletion/fsync. No new lockfile, schema, metadata repair, implicit checkpoint or stale-PID signaling. Upgrade with old readers/writers quiescent. This is cooperative trusted-local POSIX coordination, not protection from a hostile owner, NFS or legacy writers ignoring the gate.

Maintenance requires a closed Catalog with no WAL/SHM/journal before and after inspection and opens it with mode=ro,immutable=1 ONLY while holding that common exclusive gate. Verify original application/schema, Catalog inode and every row, in one read snapshot; do not ignore a live WAL. Do not reuse the ordinary constructor/reader and then claim no transient SQLite metadata creation. Read-only plan creates no files, directories, journals, locks, plans or receipts in the store.

Read canonical/hash-verified manifest metadata and validate exact three roles/raw,normalized,report and restricted references. Stat every referenced object for safe identity/type/declared size, but do NOT open, parse or return its retained raw/normalized/report payload. Maintenance protects references; normal dataset reads retain full content verification. Only unreferenced objects are SHA-streamed, boundedly, to verify their CAS names. This is not replay certification or permission to inspect confirmation evidence. Both CLI commands reject split=confirmation before plan file, identity, path or Catalog IO.

Fixed v1 scan limits:4096 total manifest/object entries,64MiB per object,256MiB actual manifest plus orphan-content bytes read,4MiB canonical plan bytes. Exceeding any bound returns BLOCKED without a deletable subset. Reads exclude atime from fingerprints. File metadata is regular, same user, nlink1; pin root/objects-parent/objects/manifests directory device/inode, never directory mtime/ctime that own deletions change. No arbitrary recursive traversal.

## Frozen plan

`dataset_retention_plan_v1`, schema_version1, has exactly kind,schema_version,status,policy,observed_at_ns,store,reference_sha256,files,protected_objects,candidates,diagnostics. Plan ID is SHA256 of its bounded canonical bytes. No secret, raw payload or absolute source path. Identifiers are lowercase SHA256; integers are signed64, nonnegative, bool/float forbidden. Status is READY or BLOCKED.

policy has exactly min_age_seconds,max_entries,max_object_bytes,max_scan_bytes. Fixed bounds above; minimum age defaults86400 seconds, explicit0 allowed, maximum315360000. Capture observed_at_ns once from current filesystem/UTC time; the cutoff is max(0,observed_at_ns-min_age_seconds*1000000000). A candidate is an unprotected, hash-verified CAS entry with max(mtime_ns,ctime_ns)<=cutoff. Future/young entries remain retained. This is filesystem-entry age, not market capture time, a research clock or authority to expire evidence.

store is null for an unavailable BLOCKED snapshot or has exactly root,objects_parent,objects,manifests, each with exactly device,inode. files is sorted by path, unique, each with exactly path,sha256,size_bytes,device,inode,mtime_ns,ctime_ns,nlink,content_verified. Paths are only objects/sha256/HASH or manifests/HASH.json. Manifest/orphan contents are verified; retained referenced payloads have content_verified=false and their declared identity is not presented as a newly verified content digest. protected_objects and candidates are sorted unique object IDs; candidates must be a subset of unprotected verified files satisfying the frozen age policy.

reference_sha256 hashes canonical metadata `{catalog:[{dataset_id,manifest_sha256,sealed},...],manifests:[DATASET_ID,...]}` with sorted rows/manifest IDs. All valid physical manifests contribute even when unindexed; each catalog row requires its valid manifest. Manifest IDs bind their complete metadata. READY has a complete snapshot, no diagnostics and a reference digest. BLOCKED has candidates=[], one or more fixed diagnostics, no partial deletion authority; incomplete snapshots may be omitted. Diagnostics: maintenance_busy,store_unavailable,unknown_entry,unsafe_entry,invalid_catalog,invalid_manifest,missing_reference,invalid_object,sidecar_present,scan_limit. No guessed root, silent repair or arbitrary diagnostic paths.

## Explicit apply and recovery

Plan CLI: `plan-dataset-retention --store PATH [--min-age-seconds 86400] [--split development]`. Output exact envelope kind=dataset_retention_preview_v1,schema_version1,plan_id,plan,execution_authorized=false. A successfully reported BLOCKED plan is a successful read, not a permission grant. Persist stdout outside the store.

Apply CLI: `apply-dataset-retention --store PATH --plan FILE --expected-plan-id HASH [--split development]`. Require exact canonical plan/envelope and explicit expected ID, then acquire the same EX gate. No arbitrary filename is a deletion candidate. Recompute actual complete references, identities, inventory, hashes, policy classification and fingerprints before the FIRST unlink. Reject changed roots/references, new objects, noncandidate changes, recreated candidates even with equal bytes, or an unsafe/incomplete snapshot. Do not silently recompute a broader candidate set.

Explicit repeat permits absence ONLY of original planned candidates. Compare current state against the original full snapshot with those candidates removed; every remaining candidate/noncandidate and manifest fingerprint must agree. Changed reference roots or re-created candidate inode/ctime still refuse all. A missing candidate is merely observed already_absent; it is not evidence of who removed it, historical credit, refunded quota or a reconstructed prior result.

Result exact fields: kind=dataset_retention_result_v1,schema_version1,plan_id,status,intended,unlinked,already_absent,removed_logical_bytes,diagnostic. Lists are sorted unique original candidate IDs. status APPLIED requires every intended entry now absent and objects-directory fsync successful. On a fresh success, unlinked==intended and already_absent=[]; on explicit repeat, intended partitions into unlinked and already_absent. removed_logical_bytes counts ONLY entries successfully unlinked THIS call, not physical freed bytes or missing-entry credit. An empty READY plan is valid and changes nothing.

Statuses REFUSED/PARTIAL/IO_UNCONFIRMED are explicit non-success. REFUSED before unlink changes no object; PARTIAL stops immediately after an unlink failure with the known removed subset; fsync failure or uncertain IO is IO_UNCONFIRMED, even if names were observed absent. Preserve diagnostics, never imply atomic rollback/all-success or automatic retries. Explicit repeat may revalidate and fsync CURRENT absence; it cannot reconstruct the prior call. Result diagnostic is null only for APPLIED or one fixed code blocked_plan,plan_mismatch,snapshot_changed,unlink_failed,fsync_unconfirmed,maintenance_busy,store_unavailable. CLI apply exit0 only APPLIED, other statuses exit9; invalid input/IO exceptions retain visible existing CLI error handling.
